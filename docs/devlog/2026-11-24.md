# 2026-11-24 (session 2)

## Goal
Complete the Pillar 1 pipeline end to end on a public testing journal.

## Done
- Chose a public data source: Kaggle "Historical Trade Data" (Hyperliquid fills, CC0) —
  [ADR-0004](../decisions/ADR-0004-testing-journal.md). Downloaded from a public mirror whose file
  size matches the Kaggle listing; SHA-256 recorded in `provenance.json`.
- `loaders/hyperliquid.py`: fill-to-round-trip reconstruction —
  [design](../design/fill-reconstruction.md). 7,562 fills -> 422 trades; 2 gaps discarded; 1 flip.
- `scripts/build_testing_journal.py`: reproducible build of `data/testing_journal/`.
- Outcome unit decision — [ADR-0005](../decisions/ADR-0005-outcome-unit.md).
- Inference modules: `bootstrap`, `sharpe`, `bayes`, `multiple_testing`, `monte_carlo`, `sizing`,
  `synthetic`; choices in [ADR-0006](../decisions/ADR-0006-inference-methods.md).
- `report.py` + `scripts/run_report.py`: full report with four figures.
- Tests: 39 passing (known-answer tests for every method).
- Write-up drafted with results; interview pack and two learning notes.
- Removed emojis from all repo markdown.

## Bugs / issues (symptom -> cause -> fix)
- Kaggle download needs login -> no API credentials on this machine -> used a public GitHub
  mirror and verified the file size against Kaggle; recorded the hash.
- Unsure whether `Closed PnL` includes fees -> undocumented in the source -> recomputed P&L from
  entry/exit VWAPs; median relative difference 4e-7 proves it is gross of fees, so fees are
  subtracted separately.
- Timestamps only to the minute -> many fills share a timestamp -> stable sort on original row
  order as tie-breaker.

## Findings worth remembering
- The edge is highly significant, but losses are concentrated: top 5 losses = 97.6% of USD losses.
- Kelly leverage (6.7x) is pinned just under the wipe-out bound from the worst trade (7.1x).

- Sensitivity: Politis-White block length; volatility-normalised outcomes.

## Done
- `ingest.py`: alias-based column mapping with explicit overrides, number/direction/time
  parsing, derivations (direction, exit time, P&L, net P&L, risk, ids, notional), cost sign
  convention, row-level validation by file line, conversion report —
  [design](../design/journal-ingest.md), [ADR-0007](../decisions/ADR-0007-journal-conversion.md).
- `cli.py`: `trade-journal check | convert | analyse` console command; JSON mapping templates;
  `mt4` preset.

  spreadsheet).
- Report: generic header text; warning below 30 trades.
- Tests: 51 passing (12 new).

## Bugs / issues (symptom -> cause -> fix)
- Row problems reported as "row 3" for the 4th data row -> DataFrame index is 0-based and
  excludes the header -> report file line numbers (index + 2).
- `check` failed with a pandas `parse_dates` error on non-canonical files -> dates parsed before
  checking columns exist -> check required columns first, then parse.
- Mapping template blanks broke `--mapping` -> empty strings treated as column names -> blanks
  now mean "auto-detect".
- Converted journals without risk could not be analysed -> report needs risk or notional ->
  converter now outputs notional.
- Derived values showed float noise (200.00000000000017) -> binary floating point -> write CSV
  with 10 significant digits.
